# Feature: web parity, second round

## 1. Goal

The browser got, over 2026-10-25 and 26, features the phone does not
have: inbox paths opened in place, blocks copied with one touch, the
prompt row focusing the line, completion of any word from the screen,
and fit that keeps still while a line is composed. The phone also still
scrolls worse than the browser: the owner reports struggles with it,
to be pinned down first. This plan brings the phone level with the
browser, as `docs/plans/2026-10-25-round-watch-and-web-parity.md` did
for the previous round. Core plans this follows:
`muxway/docs/plans/2026-10-26-inbox-files-in-place.md`,
`2026-10-26-screen-to-line.md`, `2026-10-26-fit-keeps-still.md`.

## 2. Design

- **Files in place.** `Api.readFile(address, name)` calls
  `GET /v1/panes/{address}/files/{name}`. A path of the inbox's shape in
  a row is underlined like a web address; a tap opens an image in a
  sheet over the pane with the name, the size and a close, pinch to
  zoom; other types go to the system viewer through a content URI of
  the app's cache, deleted when the sheet closes. A tap on it is not a
  tap on the pane.
- **Copy a block.** `Blocks` in the protocol module, the browser's
  rules. A long press on a row of a block copies the block without
  markers and shows a snackbar `copied, 12 rows`; the row flashes.
- **The prompt row.** A tap on the cursor's row, from the listing's
  `cursor_y`, focuses the text line and raises the keyboard, after the
  tap the program gets when it has the mouse.
- **Zip in the inbox.** The protocol module's type list gains
  `application/zip` (`.zip`), so the picker and a share of an archive go
  through; the sheet shows an archive as its download only.
- **Completion.** `Complete` completes the word at the caret, with the
  screen's words after the program's commands, as the browser does;
  closes #12.
- **Fit while composing.** The tile's fit measures the body as if the
  line were one row (`slack`); the body scrolls instead.
- **Scrolling.** Before anything is changed, a session with the owner
  on the phone, recorded in this plan: what a drag does on Claude Code
  (alternate screen, mouse on), on a shell's scrollback, and when the
  rows do not fit. The likely suspects from the code: the drag threshold
  against the wheel's row size, the queue's four pending requests while
  Claude Code redraws, and the bottom pin fighting a drag. The fix is
  decided from what is seen, not guessed here.

## 3. Protocol and API changes

Uses the core's new endpoint and the cursor fields; nothing of its own.

## 4. Security analysis

- The file sheet shows bytes from the hub as an image only; no WebView.
  Other types are handed to the system by a `FileProvider` URI of the
  app's own cache, read permission only, revoked on close.
- The clipboard is written on the long press only; nothing is read.
- Completion and blocks are from the rows on screen; nothing is sent.
- Logs: the app logs no content, as before.
